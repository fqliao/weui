01 / WHY WEUI

测试人员确认业务，
平台承担重复工作。

把“浏览网站、编写用例、反复执行、定位问题”连成一个工作流，让 AI 的发现成为可维护、可验证的测试资产。

从临时对话到可维护资产

探索结果进入用例库

草稿保留需求与页面来源；人工校准步骤和预期后发布。用例有版本，后续可编辑、批量测试和回归。

从重复推理到稳定复用

能静态执行的先静态执行

明确的操作、数据、等待和断言交给 Playwright。定位变化再逐级启用 Midscene，减少不必要的模型调用。

从一个结论到完整证据

结果可以解释、可以复核

真实画面、步骤、断言与缓存路径关联展示；每个用例保留耗时、Token、人民币预估费用及历史趋势。

本阶段结论：已形成可体验的测试闭环，并验证了特定用例的零 Token 静态回放。节省来自复用操作与确定性检查；本次业务结果仍会重新验证。
02 / USER JOURNEY

一个入口，五步完成测试闭环。

用户通过 Web 界面使用。首次接入完成网站与身份配置，日常从“用例库”选择用例直接运行。

04 / EXECUTION STRATEGY

先复用，再推理；
结果始终重新检查。

沿用平台约定的缓存级别：二级是静态执行记录，一级是 Midscene 原生缓存。默认逐级回退发生在当前步骤，避免重跑已经提交的整条用例。

DEFAULT ROUTE

二级静态 → 一级缓存 → 实时推理

确定性强的部分交给程序，无法静态确认的部分交给 AI。三种运行入口可主动选择起始层。

L2 / STATIC

复用操作与检查契约

校验入口与目标语义，注入本次参数，执行明确操作，并重新检查结构化预期。

全部环节适用时：0 模型调用、0 Token
L1 / MIDSCENE CACHE

复用规划与定位

恢复 Midscene 原生计划与 XPath 等定位信息。等待和断言结果不直接复用。

命中可减少调用；部分环节仍可能需要 AI
AI / REALTIME

重新观察与推理

页面变化或缓存缺失时分析当前页面，执行原步骤、核对原预期，并记录新候选缓存。

验证通过、证据保存且清理无异常后发布
本次执行方式 读取与执行顺序 成功后的处理
二级优先 · 默认 静态执行 → Midscene 缓存 → 实时推理 更新适用的执行记录；首次明确配置也可直接静态运行
一级优先 跳过二级，先尝试 Midscene 原生缓存 从成功执行中生成二级记录，并保留 / 更新一级
实时推理 跳过旧缓存，按当前页面重新分析 从通过的操作与验证重建适用的一、二级缓存

用例设置为“始终实时推理”或页面被识别为不适合缓存时，不读取或发布缓存。页面中的 Canvas、iframe、部分自定义组件或动态图形会保守进入实时路径。

为什么使用 JSON 静态指令？

操作表达与执行引擎分离。JSON 是平台受限 DSL，由固定 TypeScript 解释器调用 Playwright，便于校验、参数绑定、逐项差异、版本管理和界面编辑。当前不动态执行模型生成的任意 TypeScript，也没有另加第三级。

什么变化应当触发回退？

检查 URL、控件身份、唯一性、可见性和可操作性；输入后核对本次值。整页截图与 DOM 指纹用于诊断，不以“与上次完全相同”为通过门槛。目标不可用可以回退，明确的业务断言失败则保留失败。

哪些步骤仍需要 AI？

  • 未明确定位的新控件：首次需要 AI 定位，成功后可沉淀。
  • 自然语言组合流程：首次需要规划；当前自动提取以点击和输入为主。
  • 尚不能完整表达的视觉与业务语义：继续由 Midscene 判断或人工校准。
  • 缓存不适用的页面或“始终实时”用例：直接实时执行。

用例库可展开逐项能力；报告显示“二级静态执行”“一级缓存执行”或“已使用 AI 实时推理”。登录准备与清理也会影响整条用例的模型消耗。

06 / CONTROLLED DISCOVERY

探索有阶段，收敛有依据。

Agent 负责观察、导航和测试设计；当前探索不自由提交业务表单。正负向操作放在审核后的正式用例中执行。

PHASE 01

主链路

识别标准流程与业务入口，生成正向草稿，建立可验证的基线。

晋级依据：发布后的所选基线正式运行全部 PASS
PHASE 02

边界探索

结合需求与领域规则设计留空、格式错误、边界与提示验证。

晋级依据：正式结果确定，未知副作用及清理问题已排除
PHASE 03

发散探索

扩大到预览、帮助、侧栏等入口，寻找未覆盖路径并沉淀新草稿。

新增发现仍须经过人工校准与正式验证

操作收敛：避免反复做同一件事

记录起点、目标、动作和结果，让下一次规划看到历史；调度器拒绝重复目标或高度相似操作。

路径收敛：优先走新的有效路径

以 URL、标题和控件形成状态签名，比较历史路径；重复页面不增加覆盖数，并受页面数、动作和时间预算限制。

当前探索支持 1–8 个观察页面（默认 4）；需求与页面事实、待确认假设分别保留。观察完成不等于业务通过，也不代表全站覆盖。
