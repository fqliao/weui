# 网站探索与用例沉淀

## 使用流程

1. 左侧进入 **探索用例 → 新建网站探索**。选择已接入的网站和登录身份，或直接输入新网站地址。需要登录时先到“登录会话”配置测试身份。
2. 粘贴需求正文，或导入 UTF-8 TXT / Markdown。正文最多 40000 字；Word / PDF 当前可粘贴正文。填写业务角色、范围、规则和验收标准，每条需求一行，系统按 R1、R2 等编号保留原文。
3. 指定入口及最多观察的页面数（1–8，默认 4），点击 **开始探索**。每次使用网站配置的独立浏览器；Deep Agents 根据需求选择导航，Midscene 观察截图、操作导航，并保存页面证据。可随时停止。
4. 查看页面观察、截图及未覆盖项。Agent 建议生成 0–6 条草稿（服务端上限 12），没有足够依据的新用例时允许空结果，不为凑数编造预期。草稿标注“需求依据 / 页面观察 / 待确认假设”，引用对应需求、领域规则和 P1、P2 等实际页面。
5. 在草稿列表点击“审核校准”，右侧抽屉内校准功能、入口、登录身份、前提、操作、预期及清理步骤。**先保存修改，再填写审核意见、勾选确认并发布**。不适用的草稿可驳回；所有审核保留版本和审计记录。
6. 点击 **去用例库测试**，进入统一用例库并预选已发布用例，调整选择和浏览器后运行。正式执行使用现有 Midscene 用例执行器、隔离会话、预算及证据报告。发布后的用例也可在“用例库”继续维护；探索中的审核版本保留。

探索列表按网站、名称、待审核 / 探索中筛选，显示实际观察页数、待审核及已入库数量，并支持服务端分页。默认隐藏停用网站的历史探索。

探索完成只说明已整理草稿，不产生 PASS 结论。页面现状不是需求正确性的证明；后台持久化、库存、账务等必须另配业务证据。正向、负向预期应拆成独立用例，避免在同一结束状态中互相矛盾。

## 分阶段与双层收敛

参考用户提供的《探索失控：分阶段 + 双层收敛》实践，探索分三阶段推进，不一次性无限发散：

| 阶段 | 目标 | 进入下一阶段的依据 |
| --- | --- | --- |
| 主链路 | 找到标准业务入口，梳理必填字段、有效数据及目标闭环，沉淀正向基线用例 | 人工审核发布并正式执行，所选基线全部 PASS；仅观察页面不算走通业务流程 |
| 边界探索 | 注入需求、已发布领域规则及通过的基线，设计留空、错误格式、业务边界和前端提示用例 | 上一阶段正式结果已确定，允许 PASS / FAIL；阻断、证据不足、未知副作用及清理失败不得推进 |
| 发散探索 | 基于完成的边界验证，扩大到预览、帮助、侧栏等非主流程入口，寻找未覆盖路径 | 按相同人工审核、正式测试和证据流程沉淀 |

新建探索时选择阶段；后两个阶段必须选择同一网站的上一阶段探索与其正式验证记录。服务端检查基线用例确实来自上一阶段的审核发布结果，不能用另一网站、普通浏览记录或未知结果跳过阶段。一个基线运行可以代表本轮明确选择的用例子集，不声称整个网站已覆盖。

```mermaid
flowchart LR
    A[主链路观察与草稿] --> B[人工审核发布]
    B --> C[正式测试全部 PASS]
    C --> D[边界观察与负向草稿]
    D --> E[人工审核与边界测试]
    E --> F[结果确定且清理无异常]
    F --> G[发散探索与新路径草稿]
    G --> H[审核后纳入正式回归]
```

**操作收敛**：记录导航的起点、目标、文字与实际结果，每次导航规划都看到已执行序列。相同起点上的同一目标或高度相似操作会被调度器拒绝，不由提示词自行决定是否重复。

**路径收敛**：对 URL 与页面标题、控件形成状态签名，比较历史状态，相同 URL 下相似度达到 0.94 的页面不新增覆盖数。候选路径按历史路径相似度计算新颖度；最近动作发生重复或失败时，提高新路径的优先权。模型只能选择当前已出现的链接 ID；重复状态和失败不会无限重试，仍受页面、动作、模型次数及总时间预算限制。详情页可查看动作与路径记录。

本版将实践中的“执行标准流程 / 留空填错并验证”放在**人工审核后的正式测试阶段**进行，探索阶段负责观察与测试设计。因此可以控制写入授权和业务清理，也不会把一个未经确认的预期循环强化为事实。受控按钮导航、表单交互式探索及弹窗状态图尚未开放；“打开弹窗 → 取消 → 再打开”类动作当前不能由探索 Agent 自由调用。

## 本版边界

- 探索复用已授权登录配置；登录由平台完成，生成步骤不重复登录。凭证不交给规划 Agent。登录动作可能建立服务端会话，关闭浏览器不等于服务端注销。
- 登录后只开放页面观察与已出现的导航链接点击；不开放表单填写、业务提交或任意浏览器脚本。拦截非 GET / HEAD / OPTIONS 网络请求，过滤删除、提交、退出、支付等导航。网站若用 GET 实现写操作，仍应只接入授权测试环境。
- 依赖 POST 查询、按钮导航、弹窗、文件上传、验证码以及必须写入才能到达的页面，会成为未覆盖或人工补充项。当前没有开放“探索中随意提交业务数据”的开关。
- 可以生成后续包含写操作的测试草稿，但操作、数据及清理须由审核人员确认。清理方式不明确时不会编造删除操作。
- 草稿存放在独立表，不进入正式用例目录。发布接口校验版本、项目权限、网站地址和登录身份，并原子创建正式用例；重复审核不会重复发布。
- 执行最多 10 分钟，150 个动作、60 次模型调用、150000 tokens。视觉费用仍按现有机制显示未知，实际计费限制应配置在模型服务网关。

## 工程实现

- `packages/discovery/src/routes.ts`：探索创建、启动、查询、草稿编辑及审核发布。
- `packages/discovery/src/executor.ts`：Deep Agents 探索循环与 Midscene 页面观察、导航、截图和草稿生成。
- `packages/discovery/src/policy.ts`：导航限制和草稿来源校验。
- `packages/discovery/src/convergence.ts`：阶段基线校验、动作重复拦截、状态相似度与路径新颖度排序。
- `packages/contracts/src/discovery.ts`：需求、观察与候选用例契约。
- `apps/web/components/discovery.tsx`：完整 Web 入口与人工审核界面。
- `Discovery` / `DiscoveryDraft`：持久化需求、观察、草稿与审核版本；复用 Task / Run / Outbox / Worker 的队列、租约、取消、证据及预算。

已有部署执行 `pnpm db:generate`、`pnpm db:migrate`、`pnpm build` 后重启 `pnpm start`。Windows 更新 Prisma Client 时先停止本项目应用进程，避免引擎 DLL 被占用；数据库和被测网站无需停止。
