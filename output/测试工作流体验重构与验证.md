# WeUI 测试工作流体验重构与验证

2026-09-15

## 用户流程

**探索用例 → 审核校准并入库 → 用例库执行 → 测试记录与回归。**

| 入口 | 用户在这里完成什么 | 下一步 |
| --- | --- | --- |
| 探索用例 | 选择网站、提供需求；查看待审核数量、已入库数量、探索进度；在右侧抽屉修改并审核草稿 | 发布后进入用例库，预选本次发布的用例 |
| 用例库 | 搜索、按功能筛选、跨页勾选、右侧校准；在运行栏选择浏览器 | 单条立即测试，或运行所选用例 |
| 测试记录 | 按次查看运行，筛选进行中、需关注或全部通过；查看真实浏览器过程和验证详情 | 一键回归原快照；修改用例后从用例库重新执行 |

移除了重复的流程卡片、说明横幅、独立的全站选例入口和单独占用整块区域的浏览器设置。`#/new` 保留兼容，显示与 `#/cases` 相同的用例库；同一页面内切换这两个入口不会丢失选择或页码。

用例库默认展示所选网站的全部启用用例，功能用于筛选。单次最多选择 12 条，可跨功能、跨页保留选择。手动新建和探索发布的用例统一维护。用例编辑、功能编辑和探索审核均采用右侧抽屉；未保存内容有关闭保护，保存与错误消息显示在抽屉内。

网站选择在入口之间保留，默认隐藏停用网站的历史记录；可通过勾选重新查看。网站、登录、知识、技能及工具归入配置与扩展区域。目标规划和内置审批样例保留在用例库的“更多”入口。

测试记录以每次 Run 为单位，保留同一任务的每次回归，探索任务和 Skill 调试不会混入正式运行列表。执行状态与验证结论分列，避免把“执行完成”理解成“全部通过”。未执行的目标计划保留在次级标签。

报告用一处用例选择联动截图、步骤和预期 / 实际详情，不再重复大截图和用例切换。UI 断言的实际结果显示观察说明；时间线、版本和人民币模型费用按需展开。原始证据、报告下载、反馈和重跑保护继续保留。

## 实现

- `apps/web/components/website-filter.tsx`：三个入口共用的网站筛选。
- `apps/web/components/websites.tsx`：统一用例库、功能筛选、跨功能选择和编辑抽屉。
- `apps/web/components/discovery.tsx`：探索记录分页、审核进度及草稿抽屉。
- `apps/web/components/test-records.tsx`：正式运行记录、结果筛选与未执行计划。
- `apps/web/components/run-monitor.tsx`、`tasks.tsx`：联动的结果与过程报告。
- `GET /api/test-records`：项目权限、网站、名称、结果筛选和服务端分页。
- `GET /api/discoveries?page=1`：在筛选后进行服务端分页，返回草稿审核数量；未传 `page` 的既有调用保持数组契约。

无需数据库结构迁移。用例目录继续采用前端分页，探索和运行记录采用服务端分页。
